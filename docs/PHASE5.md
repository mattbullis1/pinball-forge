# Phase 5 — Optional workshop

Approved after Phase 4. Implemented for review on 2026-10-26. Phase 6 remains a separate approval gate.

## Core workflow and acceptance

Input: a table, placed components, dropdown rules, and optional local audio files.
Processing: validate references, store the editable data, execute contact events in the shared fixed-step Matter runtime, and package that same runtime and all media.
Output: an editable `.pinball.json` project, playable Test screen, and independent HTML5 ZIP.

Acceptance: all eight optional parts work when placed; rules support combined reactions without scripting; Test preserves editing data; missions, audio and rules survive export; Classic starts with Advanced closed; no external services or network configuration changes.

## Components and defaults

| Component | Default behavior |
|---|---|
| Multiball gate | Adds two balls once per gate per turn. A turn consumes one remaining ball only after every active ball drains. |
| Boost ramp | Animated arrows boost a ball along the chosen rotation. It is a flat 2D lane; no elevation or over/under crossing. |
| Moving obstacle | Solid bar oscillates along its rotated axis, with a 45-unit travel amplitude scaled with size. Motion transfers momentum through Matter contacts. |
| Drop target | 250 points, drops out of collision, rises after 5 simulated seconds. Rules can raise targets early. |
| Magnet | Attracts balls within 100 units scaled with size. No force inside the central 12-unit region. |
| Spinner | Pass-through bar spins on contact and slows gradually; 100 contact points. |
| Timed bonus | Doubles subsequent contact points for 10 simulated seconds. Re-entry refreshes the duration. |
| Extra ball | Awards one remaining ball once per gate per game. Restart resets collection. |

All timing pauses with the simulation. A new turn clears the timed bonus and combo. Missions and collected extra-ball gates persist until restart. The default game begins with three remaining balls including the current turn.

## Visual rules and missions

Open **Advanced +**. Choose the trigger part and action, then **Add rule**. Multiple rules may share a trigger. Actions: award points, flash a part, play imported sound, activate/deactivate a part, add two balls, award an extra ball, timed bonus, spark burst, and raise all drop targets. Optional **Once per game** prevents repeat rewards. Actions do not recursively generate hit events.

**Adjust → Advanced behavior → Active at start** lets a part begin inactive. Deleting a referenced part removes its rule links and mission requirement in the same undoable edit. Rules can be removed and recreated. Boundary walls are excluded from the affected-part picker to preserve the normal table outline controls.

Combo scoring rewards consecutive different scoring parts within two seconds: +50, +100, +150, and so on. The base contact award is multiplied by the timed bonus; explicit rule points, combo awards and mission rewards are fixed values.

A mission lists parts to hit at least once and awards its completion points once per game. Progress and completion appear beside the score. No code or expression entry is exposed to users.

## Audio

Import WAV, MP3, Ogg or WebM through the workshop. The browser checks metadata decoding; unsupported files report errors. Audio is embedded in project data and extracted to generated relative filenames in game ZIPs. Select a file for looping music or reference it in a sound rule. Sound toggling, pause/resume, restart and Back to Build manage music and active clips. Playback rejection is reported once per attempt, not retried every frame.

The Workshop's two WAV files are original synthesized notes generated by `src/workshop.ts`, under the repository MIT license. Imported media retains its own licensing. No new dependencies or services were introduced.

## Remaining limits

Physical tablet input and a separate-device LAN test are unverified. The browser accepted WAV import and playback produced no error message; speaker output and perceived audio quality have not been listened to through this tool. Other audio codecs depend on each browser. Browser workflows were exercised through CUA, not a committed browser regression suite. Large media collections, many simultaneous balls, and exhaustive rule combinations have not been stress-tested. Direct `file://` opening and physically disconnected networking retain the Phase 4 verification limits. Physics is an arcade 2D model. These are review limits, not claims of universal compatibility.
